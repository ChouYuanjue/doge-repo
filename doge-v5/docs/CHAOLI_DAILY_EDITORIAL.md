# 超理日报：采编与学术通讯版式

## 定位

本刊报道公开论坛讨论在**刊期对应的北京时间自然日（00:00–次日00:00）**内真实发生的论证、问题和新进展；它不等于论坛首页汇总，也不冒充独立核实的研究成果。

官方 #今日活跃 JSON 只负责发现候选主题。该索引使用滚动窗口，可能包含昨天晚间的帖子；因此先逐帖核对楼层时间，再**排除所有只有昨日回复的候选主题**。真正的事实依据是具有楼层号、作者、时间和永久链接的公开正文。引用楼层时严格区分引文与该楼作者的原话。

## 采编过程

1. 起源：从每个主题第一页提取至少前四条楼层，了解原题、主张与主要疑问。
2. 本期：末页倒查当前日期的更新，越过当日零点边界再多读一页前情。昨天夜间的楼层只充当上下文，不能写为今天新发生的事。短帖全部读取，长帖保留起源、历史抽样、相邻前情和当前更新。
3. 证据分层：向编辑模型明确标记 opening_background、historical_context、prior_turn_context、today_update、previously_discussed，避免误把旧帖推导说成今日新成果。
4. 连续报道：若前一天该主题确曾发表带有效楼层证据的日报，将其正文和引用作为差异对照。模型必须说明新变化，不重复昨天文稿。旧的401空白日报不能充当历史基线。
5. 按需补查：模型可以索要最多3个缺失楼层号。服务端只允许检索当前真实主题的数字分页，最多7页/主题、32秒/主题；每期最多6个主题进入一次第二轮采编。
6. 信息密度：文章篇幅跟随本期更新的实质内容，不随历史楼层总数机械增加。模型精读至多52楼，并可获取其余最多80条当天楼层的短索引，索取需要深读的全文楼层。纯顶帖、轻量追问写成简讯；没有真正研究进展时允许整期**零头条**。
7. 校验：稿件必须引用存在的真实楼层且至少引用一条当日更新。若引用号不合法，最多3个主题各追加一次带明确合法楼层清单的独立纠错，绝不直接补造引用。仍失败或 PDF 编译失败则不推进发送水位。

每期的清单记录日期、被抓取页面、开头/当天楼层、往期参考、追加补读楼层以及模型真正使用的证据，供人核查。

## 版式

采用独立的 A4 单栏 XeLaTeX 学术通讯，参考严肃学术通讯的标题层级、纸张结构与信息密度；没有复制其他刊物的模板源码，重点适配 QQ 中以 PNG 逐页预览的阅读方式。

结构：正式刊头及期号 → 有信息量时才出现的期标题 → 简短全期导语 → 编号、级别和板块 → 各篇标题 → （仅专题/头条有）短导语 → 中文技术正文 → 可点击的真实楼层证据及原帖。正文10.6pt、行距17.8pt，Noto Serif/Noto Sans CJK，中性色与低饱和强调色。

一栏比旧版拥挤双栏便于手机连续阅读；正文自然跨页，禁止强行裁切、不以填满纸面为目标。Latin/Greek 字体明确使用 Nimbus Roman/Nimbus Sans 的 `.otf` 文件（与 Noto CJK 配合），避免 e+π 等数学符号因默认字体或旧式 Type1 字体回退而丢字。所有外部内容转义后才进入 TeX，Tectonic 继续使用既有沙箱。

## 限制与验收

论坛删除的楼层、权限限制、纯图片与不可解析内容无法视为完整证据。长帖最多回溯18个最近分页，若无法扫描到截止时间，明确标识覆盖不完整。模型输入最多52条有角色标记的楼层，防止成本失控。

通过真实论坛数据生成学术通讯 PDF 与逐页 PNG，并逐页检查中文字体、可点击楼层链接、页码与分页。QQ 投递改为 NapCat 独立 upload_group_file 群文件上传 PDF，加上纯图片节点的合并转发；两通道分别计成功，避免合并转发内嵌文件的兼容性问题与重复发送。测试用桩验证通信序列，不主动向实际群发消息。
